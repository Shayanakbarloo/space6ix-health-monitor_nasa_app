# Backend integration plan

The Node 24 HTTP server uses SQLite for sessions, check-ins, events, messages and emergencies. Research is a separate read-only export behind the existing bearer session check. Private crew routes must use the existing crew/medical-officer role check, with the surgeon's delayed message workflow kept separate.

The current app merges user-entered check-ins with a deterministic mission simulation (mission settings, day, crew baseline and scripted event windows in simulatedCrew.ts). Inputs include heart rate (bpm), SpO₂ and hematocrit (%), blood pressure (mmHg), glucose (mg/dL), temperature (°C), sleep (hours), ultrasound (mm), leukocytes (thousands/µL), vitamin D (ng/mL), mass (kg), urine (L/day), exercise sessions and mood. Cabin data includes CO₂ (mmHg) and dose equivalent (mSv). The triage rules cite source IDs in sources.ts, including OSD-569 reference ranges, NASA CO₂ guidance and published ultrasound research. Several change thresholds are explicitly demo parameters. buildDay combines feeds and findings. BodyScan takes surface hotspots and derives organ highlighting from existing signal IDs in anatomy.ts.

The integration exposes research by study and system without passing publication values to triage or the hotspot renderer. Process CBC, CMP and cardiovascular assays first, then urine, experimental synthetic analytics and environmental data. Existing tests use Vitest, and npm run build runs TypeScript and Vite. Preserve attribution for BodyParts3D and HuBMAP HRA (CC BY 4.0) and NASA OSDR data. The checkout has no standalone software license file. No external application code is incorporated.
